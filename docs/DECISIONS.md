# Stage 1 decisions

## Provisional decisions made

1. Kept the supplied 24-table relational design and used MySQL 8/InnoDB/utf8mb4.
2. Added explicit timestamps and indexes where future API queries need them.
3. Moved `grade_scale` before `enrollments` in the creation order so the final-grade foreign key is declared inline and the schema script remains safely rerunnable.
4. Added `uploaded_files` before syllabi/submissions/documents because it is a shared parent.
5. Kept `LEAVE` as a distinct attendance status and calculate attended classes only from `PRESENT` records. The backend must document whether approved leave is counted in any separate policy calculation.
6. Used a fixed seed reference date of 2026-10-11 and future demo dates. This avoids an empty dashboard while keeping the seed reproducible.
7. Used fictional identities only. All three local accounts use the canonical BCrypt demo hash for password `password`; this is intentionally not a production credential.
8. Payment status is not stored on fee records. It is derived from verified payment totals; submitted transaction references remain pending.
9. CGPA is not stored. The project-specific requested rule is configurable as `SUM_INCLUDED_MARKS_DIVIDED_BY_5`, rounded to two decimals.
